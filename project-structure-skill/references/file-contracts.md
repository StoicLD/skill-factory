# 文件与事实契约

## 唯一权威仓库

产品 Git 仓库存放需求、验收标准、架构、接口、决策、计划、代码、测试、构建配置、运行手册、当前状态和正式验证证据。需要回到某个 revision 时，相关代码与文档应能一起回滚。

不要为 Agent Context、协作规则或文档另建一个默认 Git 仓库。若组织已有独立政策仓库，把它视为外部依赖并固定版本或链接来源；不要把项目当前事实放进去。

## 根部原生入口

每种已确认的工具原生入口只承担地图职责：

- 声明仓库根是工作目录。
- 指向共同文档索引，并给出需要时的读取顺序。
- 保留少量真正跨任务、必须最先知道的安全或权限边界。
- 当链接缺失、事实冲突或 Git 状态不明时说明停止写入并报告。

入口不得保存详细架构、完整计划、任务流水账、重复编码规范、工具私有记忆、聊天转录或机器绝对路径。目标不超过 100 行；接近上限时把内容归入事实文档并保留链接。

不同工具需要不同语法时可以有少量重复，但每个入口仍指向同一个文档索引。不要让 `AGENTS.md` 指向一套事实、`CLAUDE.md` 再维护另一套事实。

## `docs/` 事实源

文档索引是第二层地图，说明每个权威文档回答什么问题、何时读取和谁维护。索引不是大而全手册。

按真实需求选择文档；常见职责包括：

| 事实 | 合适位置示例 | 不应放置的位置 |
|---|---|---|
| 产品目标、范围、验收 | `docs/product/` 或现有规格目录 | 根入口、私有记忆 |
| 架构、边界、接口 | `docs/architecture/` | 每个 Agent 各自一份 |
| 已接受决策 | `docs/decisions/` | 聊天摘要、临时日志 |
| 当前计划和完成条件 | `docs/plans/active/` | ignored 私有目录 |
| 质量门、发布证据 | `docs/quality/` | 只存在于 CI 输出 |
| 运维和故障处理 | `docs/runbooks/` | 个人机器笔记 |
| 协作、所有权、worktree 规则 | `docs/collaboration/` | 第二个 Context 仓库 |

沿用项目已有名称和信息架构，不为匹配示例而重命名。只有存在真实内容或已确认维护责任时才创建模块。

## 代码、测试与机械约束

文档说明意图和规则；代码与测试呈现实际行为。两者冲突是需要修复的不一致，不应靠“代码永远优先”或“文档永远优先”掩盖。

把可判定的不变量编码为 formatter、linter、测试或 CI：例如依赖方向、禁止导入、文档索引完整性、生成文件新鲜度和目录边界。错误输出应包含：

```text
违规对象：<path or target>
违反规则：<rule>
修复动作：<specific remediation>
权威说明：<relative link>
```

入口可以链接该规则，但不要复制实现细节。

## 本地私有和临时内容

仅在确有需要时使用仓库内的 ignored 目录：

- 本地私有目录可保存某工具的恢复提示、尚未验证的发现或机器特定经验。
- 临时目录可保存原始日志、导出、实验和可重新生成中间文件。

两类目录都必须被 `.gitignore` 机械排除，并满足：

- 不是产品构建、测试、运行、CI 或正式交接的依赖。
- 不存放秘密、完整聊天或内部推理。
- 不作为 Agent 间的隐式通信通道。
- 需要晋升的结论先验证，再写入对应权威文档；不要复制一份长期保留。

工具已有仓库外 session/memory 时优先使用原生机制，不额外创建本地目录。

## README 与其他入口

现有 `README` 面向人类用户，可能链接文档索引，但不能替代工具的原生入口。包管理器配置、CI 文件和代码注释也不是项目事实的总地图。

## 冲突和归属不明

- 两份正式文档冲突时，依据最近接受的决策、验证证据和负责人裁定，修复或标记过时；不要让两个版本继续充当权威。
- 入口与事实文档冲突时，以经过确认的事实文档为迁移目标，并同步修正入口。
- 私有记录与仓库事实冲突时，私有记录视为过时或未验证。
- 无法判断归属时先不持久化，在写入预览中列出候选位置、证据和所需决策。
