# 演进与单仓库迁移

## 原则

- 演进是识别职责、计算差异和应用最小变化，不是重新初始化。
- 默认保留未知内容、项目专属规则、Git 历史和用户创建文件。
- 先建立新的权威路径并验证读取链，再缩减旧入口或处置旧仓库。
- 优先使用 `keep`、`create` 和 `edit-in-place`，需要其他操作时依据本文件的授权与风险规则判断。

## 只读识别

检查：

1. 仓库和父级 Git 顶层、worktree `.git` 文件、submodule、nested Git、symlink/junction 与工作树状态。
2. 每种工具实际读取的入口及证据；不要只根据文件名猜测。
3. 入口内每一段内容的职责：地图、全局约束、产品事实、当前状态、私有记录或临时信息。
4. `docs/`、README、代码注释和其他规则文件中已经存在的权威事实与重复副本。
5. `.gitignore`、未跟踪文件、构建/测试引用和 CI，判断 proposed ignored 路径是否会成为依赖。
6. 并行工作树、当前写入者、已有计划及未提交变更。

无法可靠识别某段内容的权威性或维护者时，把它列为待决策项，不移动或删除。

## 差异表

为每条变化生成：

| 路径或事实 | 当前职责/位置 | 目标职责/位置 | 操作 | 证据 | 风险与批准 |
|---|---|---|---|---|---|

操作优先级：`keep` > `create` > `edit-in-place` > `move/rename` > `merge/archive` > `delete`。

事实迁移要记录内容级来源，不只是目标文件名。不要因为新模板存在同名章节就覆盖项目事实。

## 缩减过长入口

1. 标记必须在入口保留的启动、安全和权限边界。
2. 按职责把详细事实写入或合并到一个权威文档；已有文档优先。
3. 在共同文档索引登记该文档的用途。
4. 用真实相对链接替换入口中的详细副本。
5. 验证每个原生入口可经兼容入口到达共同索引，索引可经子索引到达事实文档，声明的读取链没有循环。
6. 对比迁移前后语义；确认无遗漏后才能删除入口中的旧副本。

## 合并多个工具的重复事实

为每项重复事实选定一个仓库内权威路径。不同入口保留各自语法和最小工具差异，但都链接同一事实。内容冲突时先请求或记录裁定，不把两个版本机械拼接成更长文档。

## 从双仓库或外层 Workspace 迁移

把旧 Context 仓库和 Workspace 根视为迁移输入，不视为继续保留的目标拓扑：

1. 固定产品仓库 revision 或明确工作树快照，同时记录 Context 仓库 revision；不要假设两者同步。
2. 分类 Context 内容：已接受产品事实、稳定协作规则、工具私有状态、原始日志/临时产物、秘密或不应持久化内容。
3. 将经确认的产品事实和共享规则写入产品仓库对应文档；保留来源和适用 revision，避免无证据复制。
4. 将仍有短期价值的工具私有状态放入宿主原生存储，或用户选定且已 ignored 的仓库内目录。
5. 不迁移秘密、完整聊天、内部推理、缓存和可重新生成的原始输出。
6. 在产品仓库根创建或修正工具原生入口，使其在仓库内直接或经兼容入口到达共同文档索引；不再经过 Workspace 路由。
7. 验证代码、测试、CI 和正式交接不依赖旧 Context 或 ignored 路径。
8. 默认保留旧路由和 Context 仓库为未处置输入。处置旧仓库或修改 Git 边界、历史、remote 需有针对这些影响的明确授权；已获授权无需重复确认。

## 添加或替换工具

先确认新工具的原生入口路径和格式。能够共享现有入口时只补充兼容的最小规则；需要新入口时创建另一个薄地图并指向同一文档索引。替换工具不触发事实文档复制，也不自动删除旧入口。

## 引入并行 worktree

并行写入前定义：基准 revision、branch、worktree 路径、每个写入者的非重叠所有权、验证命令和唯一合并负责人。worktree 是任务隔离，不是按工具永久分仓；任务结束后的删除仍按用户授权执行。

## 授权与风险

沿用会话中的有效授权。用户要求结构调整时，为实现该目标所需、范围明确且可恢复的移动、重命名、归档和无冲突事实合并，可在写入预览后继续；同步修复引用并验证内容无遗漏。不要仅因操作名称而要求逐项批准。

以下影响必须有相应的明确授权；缺少授权时先准备具体可审查的方案，再请求确认，并继续不受影响的工作：

- 超出用户目标的变更、不可恢复删除、处置整个仓库，或覆盖无法保留的用户变更。
- 改变 Git 仓库边界、历史、remote 或 submodule 拓扑；branch/worktree 操作依照已有任务授权，不一律视为高风险。
- 扩大写权限、公开私有内容或降低隔离。

事实冲突或归属不明属于缺失决策，先保留双方内容并请求裁定。晋升 private 内容前核实其权威性和共享范围；已有未提交变更应保留并与本次修改区分。模板只作参考，不能代替逐项保留项目专属内容。

## 幂等与失败

- 目标已满足时只验证并报告无操作。
- 重复运行不得追加重复链接、重复 ignore 规则或重复章节。
- 失败时保留已写入现场，准确列出成功、失败和未执行步骤；不要自动回滚未知内容。
- 未验证新读取链、事实唯一性和 Git 状态时，不宣称迁移完成。
