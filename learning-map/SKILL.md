# 学习知识地图

以知识地图和原始资料导航组织 Markdown Wiki，让读者理解领域结构，并找到适合自己的课程、教材和其他材料。默认做地图；用户明确要求时，增加单主题讲义或相互衔接的课程正文。关键概念同时有准确说明和费曼式通俗解释。HTML 仅作必要时的地图与入门导览。

## 按所需产物选择模式

| 模式 | 何时使用 | 交付内容 |
| --- | --- | --- |
| `map`（默认） | 梳理体系、系统学习、找路线、推荐资料，或只要课程规划 | 领域地图、个人主线、先修、资料评估、阶段标准和关键概念解释 |
| `lesson` | 明确要求一个限定主题的讲义、完整讲解或某一讲正文 | 实际可连续阅读的讲义、必要示范与边界、原始资料入口；不为单讲重建整个领域 |
| `course` | 明确要求带实际讲义的一套课程，或显式选择此模式 | 地图、资料路线、章节问题链和约定范围内的实际讲义 |

“系统学习”本身不触发课程创作。模式不明确时按 `map` 处理；导航与正文之间的选择会实质改变任务时，先澄清。显式模式仍服从用户的限定，例如只要课程规划就不强写正文。仅接受 `lesson` 为正式模式名。

在 `lesson / course` 中，开始组织或撰写讲义前读取 [讲义与课程](references/lessons.md)。三模式共用下述澄清、资料证据、中文 STE 与维护规则；无需为已知背景重复问卷。

## 先确定起点与目标

从当前请求和前文提取：学习对象与范围、希望能够理解或完成的事、相关基础和实际经历。目标或基础仍有影响选材的关键缺口时，集中提出必要问题，等待回答后再开始该领域的资料搜集。已有 Wiki 的读取与本地范围检查可以先做。

复用已知答案，不固定轮数。用户说“不确定”时，询问具体经历或给出易回答的背景选项，区分用户自述、Agent 判断和未知事项；不要代答后立即开搜。用户明确委托判断起点时，说明采用的假设与限制，再按该委托推进。

按选材需要了解阅读语言、偏理论或实践等条件。仅在用户有时间诉求时补充大致投入；不询问预算，不替用户排每日任务。目标与信息足以选材后，简短归纳范围与起点，直接推进，无须额外审批。

更新已有 Wiki 时先读取入口、地图和受影响页面，复用仍有效的需求，只补足本次变化的信息。

## 用资料建立地图，再选个人主线

开始资料搜集与评价前，读取 [资料发现与评估](references/materials.md)。

`map / course` 先提出待核查的主要分支与核心问题，再用课程大纲、教材目录和领域资料校正地图。把材料的主题覆盖映射到分支，发现关键缺口后做针对性补充。`lesson` 只核查本讲与必要前置资料，并说明在已有地图中的位置；没有地图时用简短定位即可。

地图交代领域全景、主要层级和有意义的跨分支关系。区分包含、先修、对比、时序、因果等关系，并使用符合主题的关系；历史主题不强套编程或数学的先修模型。节点的文字应能说明其作用，边应能说清两个节点为何相连。

在地图中标出本次目标相关主线、必要先修，以及暂不展开的分支与理由。“全面”指主要结构与当前目标得到有依据的覆盖，不要求所有分支同深度，也不按固定资源数量凑齐。

学习主线还要说明为什么此时进入下一主题：前一部分解决什么问题，下一部分处理什么限制或补足什么基础。知识关系、问题顺序与资料依据可以共同写在现有页面中，不必另建三套图。

需要阶段路线时，为每个阶段交代目标、进入条件、学习方向、对应资料和纲领性的能力标准。自我测验只给方法，例如用自己的话复述、重建论证、检查适用条件、利用原材料练习；不编制具体考题、答案或评分流程。

用户有时间诉求时，可给适合该主题的粗略时长方案，说明所需基础、大致投入、预期能力和未覆盖部分。范围与时间明显冲突时解释依据，给出取舍，由用户决定；不擅自改目标。

## 为关键概念写两层解释

撰写或更新任何概念说明前，必须读取 [中文表达与费曼式解释](references/explanations.md)。其中的中文适用规则是交付条件，逐项执行，不以“参考过标准”或写出两层标题代替。

`map` 对主线必需、构成先修门槛或容易混淆的概念给中等深度解释。`lesson / course` 在约定主题内展开必要过程与论证。准确说明定义、用途、关系与条件，再用日常语言和具体例子建立直觉，回扣正式概念；可按理解顺序融合，不强制两个重复的标题块。其他节点按需给简短说明和资料入口。

正文使用中文，术语中英对照并保持一致。先确定本次术语的中文首选名、英文名与含义，再写解释。每句只推进一个主要判断；每段先交代主题，只讲一个主题，最多六句。用明确对象与动词说明关系，新的必要术语先解释或链接前置说明。两层解释都保留必要假设、条件和不确定性。

复杂定义先用短段落逐步说明对象、条件和保证，再在表格中摘要。重要过程用同一组对象展示事件、条件与结果；必要时比较正常与受限情形，或满足与违背性质的实例。解释深度服从所选模式，不以概念卡数量或篇幅代替理解。

交付前，对每个展开解释的概念执行参考文件中的审校表，包括表格里的定义和 HTML 概念摘要。发现任一适用项未通过，先改写对应句段，再复核；检查尚未完成时如实说明，不能宣称全部通过。审校是编写职责，不给用户增加学习记录表或审校附件。

## 组织与交付 Wiki

组织页面、图谱或可选 HTML 前，读取 [Wiki 组织与更新](references/wiki.md)。遵守目的地已有规则，将读者 Wiki 与 Skill 源码分开；已有文件只按本次任务需要修改。

以清楚入口连接地图、目标主线、资料、关键概念和所需讲义，按内容拆分文件，通过相对链接复用。Markdown 本身须能完成基本阅读与导航。按实际关系选图，图前说明观察目标，图后解释符号、事件与结论；图文沿用同一术语和条件。不强制每节有图。

根据地图复杂度判断 HTML 是否有实际帮助；需要时只承载知识地图、总览和入门导航，并与 Markdown 保持一致。普通 Wiki 不必生成 HTML，不增加学习进度、模拟或练习系统。

持续维护由用户发起。根据目标变化、材料不适合或资源失效等反馈，核查并更新受影响的地图、资料及讲义，保留仍有效的结构、资料和用户内容；知识结构或目标明显变化时才整体重组。正文已写或待写状态与学习者进度分开，不建立学习记录表、打卡或后台监控。

## 按实际产物验收

1. 起点与目标有依据；关键缺口已问清或有明确委托的假设，未把未知基础写成已掌握。
2. 按模式验收：`map` 的知识关系、主线、先修与资料有依据；`lesson` 完成限定主题的连续讲解；`course` 还需地图、资料与章节问题链对应，交付承诺的实际正文。目录和第一讲不等于整套课程完成。
3. 核心推荐的用途、适用基础、应读范围与证据对应；难度与时间估计有依据，无编造的章节或核查声明。
4. 每个展开解释的概念均已按中文 STE 审校表复核并修正：术语与指代明确，句子逐步推进，段落单一主题且不超过六句；两层含义、必要条件与类比局限一致。标题齐全或一句“已遵守”不能作为通过依据。
5. 阶段只提供方向、能力标准与自测方法；讲义可有已解答的示范推理，三模式均不自行编制测验题、配套答案、评分、学习记录或每日安排。
6. 实际检查文件、内部链接、原资料引用，以及使用到的图表。生成 HTML 时检查导航与实际渲染；未渲染或未联网的项目如实标记。

交付入口与必要页面链接，简要说明采用模式、覆盖范围、主要取舍、资料核查限制和实际验证情况。资源受限时交付有依据的部分，明确缺口与继续所需条件，不以目录或标题齐全宣称完成。事实、必要条件与中文 STE 不合格时先修正；链接检查或 Agent 自评不能证明真实读者已经学会。

维护本 Skill 时才读取 [产品规格](SPEC.md) 与 [验证记录](validation.md)；它们不是读者 Wiki 的生成材料。
