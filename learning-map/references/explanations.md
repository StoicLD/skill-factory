# 中文表达与费曼式解释

在任一模式撰写或修改概念说明时必须读取本文件。下列适用于中文的规则是硬性要求：先编写，再逐个概念审校，有不通过项就改写并复核。准确解释与费曼式解释执行同一套规则，深度服从所选模式和约定主题；讲义正文不豁免这些要求。

## ASD-STE100 的依据与中文适配

本规则依据 ASD-STE100 Issue 9 中适用于概念解释的要求制定中文适配。中文可执行的要求必须执行；英语特有的词表与语法单独说明不适用，不能据此把其余要求降为建议。本适配不是官方中文标准或英文合规认证；领域定义仍以学习资料为依据。

官方依据：[Issue 9 原文](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf)、[官方常见问题](https://asd-ste100.org/STE_faq.html)、[标准维护方的介绍](https://asd-ste100.org/about_STE.html)。2026-10-19 通过官方 PDF 的正文提取核对了下表涉及的规则及描述性写作说明，替代此前仅据介绍与检索摘录作出的概括。没有逐条审计全部英文规则或复制标准词典。

| Issue 9 对照 | 中文处理 | 执行要求 |
| --- | --- | --- |
| 1.3；1.8–1.11；9.4：词义与术语一致 | 术语词表按中文与领域建立 | 同一对象使用同一首选术语，必要简称先声明；不用含义漂移的近义词替换 |
| 3.6–3.7：主体与动作 | 按中文适配 | 明确谁对什么做什么，用动词表达动作；主体确实未知时保留未知，不编造责任对象 |
| 4.1–4.2：短而完整的句子 | 直接执行信息结构要求 | 一句推进一个主要判断；补足对象和条件，不靠省略主语、关系或限定来缩短 |
| 4.3–4.5；6.2：列表、衔接与指代 | 按中文适配 | 复杂并列拆为列表；说明因果、对比或先后；“它、这、该机制”均须有确定所指 |
| 6.1：逐步提供信息 | 直接执行 | 先说明对象与必要术语，再给条件和保证；初次定义不压进多重修饰链或单个表格格子 |
| 6.4–6.5：段落组织 | 直接执行 | 每段以主题句开头，只讨论一个主题；条件展开、实例或另一保证换段并明确承接 |
| 6.6：段落长度 | 直接执行 | 每段最多六句，按主题拆段；列表项也须各自可理解，不能用分号隐藏多个段落 |
| 6.3 的英文句长及英文词典、词性、时态、拼写 | 英语专属部分不直接移植 | 不把 25 个英文词换算成汉字上限；中文仍必须满足短句、单一主要判断及信息完整 |
| 第 5 节程序性写作与第 6 节描述性写作 | 按内容区分 | 概念使用描述性解释；实际操作导航才用步骤，不把概念定义写成命令 |

正式定义、符号、量词、否定、假设和不确定性以资料为准。拆句后须能重建同一个判断，不能把带条件的保证改成无条件结论。

## 编写顺序与完成条件

1. **定术语。** 为本次需要解释的对象确定中文首选名、英文名、当前含义与必要简称。被正式定义且有通行英文名称的对象、角色、状态和保证，均列为术语，首次中英对照；不能只给标题或缩写补英文。新选译名注明其用途，不虚构“官方译名”，也不为普通词或临时说法编造规范英文名。通俗称呼首次出现时，立即说明它指哪个正式术语；后文仍用首选名，不能把换了名称误当成解释。这可作为编写辅助，不必另建文件或把词表全部展示给读者。
2. **定信息。** 列清对象、必要前提、核心保证、限制与来源。先确认这些内容，再组织文字；缺少资料时写明缺口，不用“语义、机制、边界”等泛称补空白。
3. **写准确解释。** 先用完整短句介绍对象，再逐步解释条件和结果。首次定义不同对象或状态时，分别写完整句或列表项，不把几个定义压成一句。多项不同条件分项说明，并明确“在这些条件下”指向哪一组条件。必备限定保留，篇幅不靠术语压缩。
4. **写费曼式解释。** 先选定具体讨论对象与参与者，再解释同一关系和局限。说明过程时给出可追踪的动作、先后或状态；依赖编号或版本比较的例子应给出示例值，注明它们只是自拟场景。只换成“新、旧、资源、机制”等泛称来重述定义，不算具体解释。新术语需要说明或前置入口，比喻也不能继续依赖未解释的名词。
5. **逐项审校。** 按文末审校表检查每个展开的概念、表格定义与 HTML 摘要。有一项未通过就重写相关句段，再复核；不把“两个标题都有”判为完成。

概念表格用于摘要、索引与比较。首次解释需要多项条件才能理解时，在正文展开，并从表格链接过去。纯目录或字段值无需改写成冗长段落。

前置入口必须能定位到所缺概念的说明；只链接整本书或整篇论文，不能视为已经解释了该概念。资料不足时指出哪项含义或条件仍未解释，将这一部分标为受限，不宣称该概念已完整通过审校，也不为凑齐内容编造定义。

## 选择值得展开的概念

`map` 优先解释进入主线的门槛、组织多个节点的核心概念，以及容易与相邻概念混淆的内容。说明该概念在地图中的位置，再决定需要多深；其他节点用简短定义和资料入口即可。`lesson / course` 则按约定主题展开所需关系与论证，执行 [讲义与课程](lessons.md)，不将段落缩短误当成删除中间理由。

展开解释至少交代读者理解所需的对象与定义、必要条件或保证、具体理解方式及局限，并给出原始材料入口。没有独立条件时不凑条件；不强制固定标题，必要公式和限定保留。内容按理解顺序组织，不以分栏把事实关系切断。

过程类解释保持同一组参与者、对象和记号，交代初始条件、事件、先后及结果，避免省略导致结论无法重建的步骤。需要揭示限制时，改变一个相关条件，说明结果为什么不同。重要性质按需要给满足与违背的具体实例，并指出它们对应定义中的哪个条件；这些方法不要求将所有概念扩写成完整教程。

准确说明与费曼式说明可沿同一过程交错组织，无须重复成两份正文。简短概念说明仍要足够清楚，完整讲义也仍要范围受控；字数不作为清晰度或深度的替代标准。

## 用费曼式讲述建立直觉

1. 设想向尚未掌握该概念的人讲述，用日常语言说明讨论对象，以及为什么需要这个概念。
2. 用一个具体例子解释关系或过程。发现某一步仍要靠陌生词跳过时，补足必要含义或提供前置链接。
3. 需要类比时，明确类比中的对象对应什么、哪些性质不能照搬。若直接例子更清楚，就不用类比。
4. 回扣正式概念，说明这个例子支持理解哪部分、仍需去原材料学习什么。自己能讲顺不等于证明读者已经掌握。

这是写作和自查方法，不是强制读者复述的考试流程。若提出自测建议，只给方法，不附具体题目、答案或评分表。

### 简短示例：准确与通俗表达保持同一含义

以下为自拟表达示例，不是某门课程的原文或本主题的完整教学材料。

**准确解释**：有向无环图（Directed Acyclic Graph，DAG）是一种有向图。沿一条或多条边的方向前进时，不存在回到起点的路线。

**通俗解释**：把节点想成任务，箭头表示“前一项完成后，才能开始后一项”。如果沿箭头走一圈又回到原任务，就出现了循环依赖。没有这种圈的任务图，可以帮助安排满足依赖的先后顺序。

**例子的边界**：任务只是节点的一种解释。有向无环图还可描述其他关系；图中没有依赖关系的任务，也不因此必须按某个固定顺序进行。

保留这种“正式含义—具体理解—适用边界”的对应关系；不要把任务调度的例子扩大为所有有向无环图的用途。

## 交付前逐项复核

以下各项均为通过条件；发现问题后改写，而不是只在交付末尾声明“遵循 ASD-STE100”。

| 检查项 | 通过条件 | 未通过时的动作 |
| --- | --- | --- |
| 术语 | 首次中英对照，同义称呼已归一，通俗称呼有正式对象可回指 | 补中文首选名与说明，统一后续名称，显式连接比喻与正式术语 |
| 对象与动词 | 读者知道谁对什么做什么，代词能回指 | 补足对象，把压缩的抽象名词链还原为动作或关系 |
| 句子 | 一句只推进一个主要判断，不在一句内首次定义多个对象或状态，必要成分完整 | 分别写完整句或列表项，保留或明确回指共同条件 |
| 段落 | 主题句起头，单一主题，每段不超过六句 | 按含义拆段并补衔接，不仅换行或改标点 |
| 引入顺序 | 新的必要术语已解释或有前置链接 | 先给必要含义，再使用它作定义；复杂表格定义移入正文 |
| 技术含义 | 两层说明的范围、条件、否定、量词与原资料一致 | 找回遗漏条件或错误外推，不能用简短为理由保留失真 |
| 具体理解 | 有具体讨论对象，读者可追踪关系或过程；必要比较有示例值，类比对应与局限明确 | 补对象、参与者和中间关系，删掉仅用泛称重述定义的段落 |
| 模式与范围 | 有来源入口；`map` 足以进入材料，`lesson / course` 完成约定的讲解且保留资料导航 | 补必要过程或定位，说明证据缺口；删除超出本次模式和目标的扩写 |

审校只需在编写过程中完成，交付时简短说明实际检查范围与仍存在的限制；不生成学习记录、审校打卡表或“官方合规证书”。条目数量、标题、字数或正则检查只能辅助发现问题，不能证明中文 STE 表达已经合格。
