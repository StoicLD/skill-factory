# 讲义与课程

仅在 `lesson / course` 中组织或撰写正文前读取本文件。讲义服务于知识结构与原始资料的学习，不把参考书单当作正文依据。概念解释同时执行 [中文表达与费曼式解释](explanations.md)，图文与文件组织执行 [Wiki 组织与更新](wiki.md)。

## 界定本次正文

`lesson` 围绕一个有边界的主题，说明读者基础、本讲解决的问题、读完应能解释或判断什么，以及对应原始材料。已有 Wiki 时连接相关节点与前置页；没有 Wiki 时用简短的主题定位，不额外构建整个领域地图。

`course` 用地图确定覆盖范围，用问题链确定章节顺序，用已核查资料支持每讲。每讲说明为什么从前一讲来到这里、解决什么，以及下一主题还要处理什么问题。先修顺序不自动等于教学顺序，章节目录也不能替代这些理由。

范围清楚后按用户请求持续完成实际讲义，不把整套任务默认缩成第一讲。范围未定且过大时先澄清；用户委托 Agent 划定时，说明选择的范围与未覆盖部分后推进。确需分阶段交付时明确哪些已写、哪些只是规划及其原因，不把待写目录计为已完成课程。用户仅要规划时尊重该限制。

## 组织连续解释

围绕读者需要解决的问题组织正文。以下是写作时的选择与检查，不是每讲必须复制的标题或固定顺序：

- 先建立讨论对象、必要基础和动机。需要定义才能看懂例子时，先给最小定义；避免先抛出依赖多层陌生术语的结论。
- 过程类内容选一组一致的参与者、数据和记号。给出初始条件，逐步追踪谁对什么做什么，以及事件如何改变状态或结果。
- 揭示限制时只改变相关条件，让读者看见结果为何不同。用具体情形引出新概念，再明确正式定义、前提与保证；不要把类比当作证明。
- 推理类内容从输入及前提出发，解释必要中间步骤及其理由。给出完整的已解答示范，明确它是来源中的例子还是自拟例子；不把示范改写成读者必须作答的题目。
- 对重要性质提供满足与违背的实例，或比较相邻概念的区别。反例要说明违背了哪个条件；不为了凑格式给每个名词编反例。
- 在本讲结尾说明结论适用到哪里、原资料接下来读什么，以及为何进入下一主题。自检仍给方法或原资料练习入口，不自行编制测验与答案。

准确解释和费曼式说明可交错展开，但正式含义、具体理解与局限都须可辨认。用自然段说明因果与推理，用列表表达真正并列的项；避免把连续论证拆成互不相连的卡片。每段单一主题、最多六句等中文 STE 要求对讲义同样有效。

## 按内容类型调整

| 内容 | 需要读者跟上的内容 |
| --- | --- |
| 概念与理论 | 研究对象、定义、直观例子、适用条件、相邻概念与边界 |
| 算法与协议 | 系统假设、角色、初始状态、事件与消息、状态变化、性质及代价；按主题展示正常或失败过程 |
| 工程实践 | 版本与环境、最小示例、实际或预期结果、设计理由、适用限制；未运行的代码明确标为未运行 |
| 数学与理科 | 假设、定义、符号、关键推导与中间理由、结论及反例；不能用日常比喻替代所需证明 |
| 历史与社会科学 | 时空背景、主体、史料与解释，区分事实、学界争议及推断，保留因果条件 |

这些是选择依据，不要求所有学科采用“失败后修复”的叙事，也不要求每讲包含全部类型。

## 正文依据

实际查看支持核心定义、条件与过程的对应正文，遵守 [资料发现与评估](materials.md) 的证据边界。只看到目录或摘要时，不能据此写出并宣称核验了完整机制。资料不足的部分标明缺口，或收窄有依据的论述，不用生成的细节补成来源事实。

在相关说明附近或讲义末尾给已核查的具体节名、锚点或页码，区分来源事实、原例、自拟示范和推断。自拟示范也须与来源条件一致；复用图文时核查出处与使用条件，优先独立表述。代码执行结果与预期输出分开，版本相关结论注明实际核查版本。

## 交付前检查

| 模式 | 必须由实际正文支持的判断 |
| --- | --- |
| `lesson` | 本讲问题与前提明确；读者可追踪关键关系或过程；结论、边界与原始入口对应，未用链接代替承诺的讲解 |
| `course` | 具备单讲要求；地图、资料及章节互相定位；章节顺序有理由；已写正文覆盖本次约定范围，待写或受限部分明确 |

先按中文 STE 审校表逐概念复核，再检查图文、来源与章节衔接。事实性严重错误、必要条件遗漏或术语漂移必须修正，不能由篇幅、图数或其他评分抵消。图和代码只在有实际价值时使用，分别报告渲染及运行情况。

检查的是内容是否提供了理解条件，不是认证学习者已经掌握。Agent 审阅、结构检查与真实读者试用分开记录；不向读者增加评审表、学习日志或交作业流程。
