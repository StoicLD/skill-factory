# Wiki 组织与更新

组织文件、关系图或可选 HTML 时读取本文件。页面结构由主题规模与现有目录约定决定，以下是职责，不是必须逐一创建的固定文件清单。

## 入口与知识地图

入口让读者辨认学习对象、本次目标、采用的基础假设、覆盖范围，以及先从哪里看。只保留影响指南使用的背景摘要，不建立个人学习档案或活动记录。

用领域主干组织各分支，并为目标主线提供可进入的路径。知识地图至少在 Markdown 中清楚呈现：可用分层文字、关系表或必要的图，节点链接到对应说明或资料。主干过密时拆成局部图，再链接回来。

关系表或图的边说明真实含义；先修关系可用于路线排序，包含或对比关系不自动意味着先学后学。图中的关系与正文一致。没有渲染能力时选可读的文字关系表达，或明确未验证图形渲染。

概念、资料与阶段可以组合在同一页，也可以按主题拆开。避免每个节点都新建文件；同一解释有多个入口时使用链接复用。

## 阶段与资料导航

阶段让读者看见学习目的、必要基础、学习方向、资料选读范围，以及判断是否适合继续的能力标准。把重要内容关联回地图，不仅列课程名称。

自测只提供方法，例如用自己的话解释关键关系、重建材料论证、辨认适用条件或使用原资料的练习检验理解。读者自行执行并按需要开展详细 AI 交流，Wiki 不要求回报成果或维护掌握度。

有时间诉求时，可在同一方向下解释不同预设方案的范围、深度与成果差异。日期、每日任务和学习记录不属于阶段页面。

资料目录可按用途与主题组织，并区分主线、拓展与候选。推荐与对应节点、阶段相连，避免脱离地图的长清单。核查依据和局限放在能影响选用判断的位置，不必额外建立大而重复的证据表。

## 可选 HTML

复杂地图需要概览、展开局部关系或点击进入资料时，可以生成少量 HTML；简单结构用 Markdown 即可。用户明确要求的产物形式优先。没有明显帮助时，交付时简短说明未生成的理由。

生成 HTML 时优先提供可直接打开的文件，保留 Markdown 入口，不引入维护所不需要的后端或服务。可用的交互包括主干与局部展开、节点定位、选择分支及进入对应资料；按需要选择，不要求全做。

标题、节点关系、资料与范围必须和 Markdown 一致。所有本地页面使用实际交付位置的相对链接，点击后能打开对应内容。HTML 的标题、导航与辅助说明均使用中文；概念术语采用中英对照，并与 Markdown 使用一致名称。

验收实际页面：图能读、节点和链接可用、交互能完成导航，窄窗口下内容仍可进入。只做静态检查时明确交互与渲染尚未验证。不要加入进度勾选、考试、模拟或练习系统。

## 文件与更新边界

生成前检查目的地规则与已有文件，输出到读者产物区域，不放进 Skill 源码目录。目的地未指定时在允许的工作区选择清楚的主题目录；同名但来源不明的文件先避开，已有 Wiki 则围绕本次任务修改。

入口和主题页使用可迁移的相对 Markdown 链接。检查实际文件、标题锚点和围栏；有图或 HTML 时分别验证使用到的表现形式，不把源文件存在视为渲染通过。

收到更新请求时：

1. 读取现有入口、地图与受影响的页面，确认改变的是目标、基础判断、选材、概念说明还是资源状态。
2. 针对变化核查资料，修改必要节点及其关联路线、引用和可选 HTML。
3. 保留无关的有效内容与用户原有笔记。只有目标或知识结构明显变化时整体重组，交付时说明改变范围和理由。
4. 复核内部导航及前后一致性，说明仍存在的证据缺口。更新说明关注指南改动，不创建学习历史或打卡日志。

外部资料无法核实时，保留可信的已有内容并说明限制，不能把推测的新版本替换为“已核查”。用户没有发起维护时，不启动后台搜集、监控或定期通知。
