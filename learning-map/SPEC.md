# 领域知识地图与学习资料导航 Skill 规格

日期：2026-10-16。

状态：需求设计与主要验证边界均已由用户确认，并已补充费曼式通俗解释要求。用户已另行授权制作 Skill，当前实现采用 `learning-map`；实际验证结果与限制由[验证记录](validation.md)维护。issue 发布仍等待项目跟踪配置，不作为源码制作的前置条件。

## 问题陈述

用户准备学习一个具体领域、学科、工程实践或理论时，需要先理解整体知识结构，再判断哪些内容与自己的目标有关、需要哪些基础、适合使用哪些材料，以及学习顺序是否合理。

单纯的课程与书目清单无法解释这些关系。通用路线也容易忽略读者基础、材料难度和目标范围。大模型撰写的概念说明还可能出现术语漂移、抽象表述堆叠和类比失真，使初学者难以进入原始资料。

本 Skill 需要把有依据的资料选择组织成可持续维护的知识地图 Wiki。用户主要通过原始课程、教材与其他材料学习；Wiki 承担总览、导览、取舍说明和必要的概念解释。

## 解决方案

围绕用户的基础与学习目标，构建以整体知识地图为骨架、以多份 Markdown 为主要载体的 Wiki。学习路线、资料导航、阶段判断和关键概念解释围绕地图组织。HTML 是可选的辅助产物，仅在有助于理解整体结构和入门路线时生成。

知识地图应同时呈现主要分支、层级和跨分支关系。先修依赖、包含、对比、时序或其他关系应有明确含义，不把所有关系都简化为学习先后顺序。读者可以从总览进入目标相关的主线，再进入具体资料。

“全面”以领域主要结构与学习所需内容的覆盖为依据，不以链接数量为依据。提供领域全景，同时明确本次展开范围、暂不学习的分支和已知覆盖缺口。只有目标相关主线及必要先修内容需要详细安排。

关键概念采用准确解释与面向初学者的费曼式通俗解释。两层解释共同遵循参考 ASD-STE100 制定的中文写作规则，帮助用户进入原始学习材料。

33. 作为自主学习者，我希望自行决定学习节奏与记录方式，以便指南不会演变成考试或学习管理系统。
34. 作为提出大致时间要求的学习者，我希望得到方向性的阶段规划，以便理解时间与范围的关系。
35. 作为比较不同时长方案的学习者，我希望知道各方案对应的基础、投入与可达目标，以便作出合理选择。
36. 作为目标与时间存在冲突的学习者，我希望得到有依据的取舍建议，以便自己决定是否调整目标或投入。
37. 作为学习者，我希望通过清楚的入口和内部链接阅读多份 Markdown，以便在总览、概念和资料之间导航。
38. 作为需要视觉总览的学习者，我希望有必要时获得辅助 HTML 知识地图，以便理解结构并找到入门路径。
39. 作为只需要 Markdown 的学习者，我希望不依赖 HTML 也能使用完整指南，以便按自己的工具和环境阅读。
40. 作为已有 Wiki 的用户，我希望通过反馈发起局部更新，以便修正资料、难度判断或学习方向。
41. 作为已有 Wiki 的用户，我希望更新保留仍然有效的内容，以便避免无关重写和结构反复变化。
42. 作为已有 Wiki 的用户，我希望只在目标或知识结构明显变化时进行整体重组，以便保持长期使用的一致性。

## 实现决策

### 职责与组成

- 作为独立的 Skill 源单元维护，不修改、合并或默认依赖已有的 Ten-step-learning、Book Study 或 Technical Prose。
- 逻辑职责包括需求澄清、范围界定、知识地图、资料发现与评估、概念解释、阶段导览、产物组织和局部更新。它们是行为分工，不预先规定必须拆成对应的文件、脚本或子 Skill。
- Skill 的正式名称、宿主配置、目录细分、模板和可选脚本在实现阶段按实际需要选择，不将它们误记为已确认的产品要求。

### 需求澄清与开始条件

- 从本次请求与已有会话提取领域、学习目标和相关基础。基础或目标存在会影响选材的关键缺口时，先提问并等待回答，然后再开始该领域的资料搜集。
- 不固定问答轮数，不重复询问已知信息。按需要了解语言能力、相关经验和时间诉求，不建立预算问卷。
- 用户自述、Agent 推断与仍不确定的事项应可区分。允许用户表达不确定，不凭空断言其已经掌握或完全不具备某种能力。
- 更新已有 Wiki 时先读取相关现有内容，只补充本次决策所需的变化信息，不默认重启完整需求问答。

### 地图与学习路线

- 领域地图是主要内容结构，个人学习路线是其中的目标相关视图。目录、节点说明、阶段和资料之间应能互相定位。
- 展示主要分支、核心概念与有实际意义的关系。关系说明应符合领域特点；科学理论、工程实践、历史等主题不强套同一种知识关系模板。
- 地图的领域范围、个人目标范围和实际深入解释的范围应明确。对暂不学习的分支保留必要入口与取舍说明，对证据不足的覆盖保留缺口说明。
- 不要求每个节点都独立成页，也不要求每个节点具有相同字段或篇幅。文件拆分服从导航、复用和阅读需要，不以节点数量或文件数量作为完整性指标。

### 资料发现、核查与评价

- 搜集应重点考虑世界顶尖大学的课程材料、经典教科书、与时俱进的优秀博客及业界高人气、高质量开源项目；按主题需要补充论文、官方文档、标准、讲座、习题或实验资料。
- 各来源类型是否适用由领域与目标决定，不要求每个主题都推荐开源项目，也不按固定数量凑齐资料类别。
- 科学、技术、计算机科学与数学等领域优先优秀英文原始材料；中国历史等领域根据研究对象优先合适的中国资料。语言偏好仍需结合用户实际阅读能力与材料质量判断。
- 名校声誉、作者名气与项目热度用于发现候选资料，最终选择以内容质量、适用范围、先修要求、可获取性和目标适配为依据。
- 区分广泛发现的候选资料、深入核查的主线材料和基本核验的拓展材料。主线课程检查大纲、先修要求及可获取的具体课次和作业；教材检查目录及可获取样章；项目检查文档、示例和与本次用途相关的维护情况。
- 推荐应说明资料解决的问题、适用基础、应学部分、安排理由及必要的替代或过渡材料。章节、课次、版本和其他精确定位只能依据实际核查内容给出。
- 无法取得正文或核实具体内容时，明确实际查看范围与判断限制。证据不足的资料保留为候选，不以精确定位或笃定难度包装推断。
- 难度区分数学、编程、领域基础、语言及工作量等相关维度，不强制使用一个总分。估计应说明依据与不确定性，不将未经检查的内容写成确定的学习耗时。
- 经典资料评价其持续适用的价值；前沿或版本相关材料核查相应时效。获取条件影响能否使用，价格本身不成为评分维度。
- 尽量避免付费在线课程，但不将其解释为绝对禁止。教材和工具不受该偏好限制，不设计费用评分、预算优化或采购流程。
- 仅依据实际可取得的证据说明核查状态；无法联网或材料受限时交付可支持的部分，并明确受限范围，不声称已完成全面搜集。

### 两层概念解释与中文表达

- 只对理解主线必需、构成先修门槛或容易混淆的关键概念进行中等深度解释。其余概念按需要提供简短定义、位置说明与资料入口。
- 准确解释依据可靠资料，说明定义、用途、关键关系及必要的假设和适用条件。概念事实的来源与写作规则的来源应区分。
- 费曼式通俗解释使用日常语言、熟悉场景和具体例子，解释对象、过程及其作用。必要的新术语先说明或提供前置入口，不用连续堆叠的陌生术语替代解释。
- 使用类比时交代与真实概念的对应关系和局限，再回扣正式概念。自拟例子不冒充原资料中的例子，直观解释不替代严格定义、证明或必要条件。
- 两层解释都遵循参考 ASD-STE100 制定的中文写作规则：术语稳定，对象明确，条件完整，句子之间的关系清楚，避免抽象修饰堆叠与无依据的表述漂移。
- 术语采用中文与英文对照，其他说明使用中文。同一概念首次确定名称后保持一致，必要简称应能回指完整术语。
- 写作规则应说明直接采用、经中文适配与不适用的部分，不机械移植英文词表、语法或词数限制，不宣称中文文本已通过英文标准的合规验证。
- 2026-10-19 根据实际使用反馈明确执行方式：中文适用规则作为交付条件。每个展开的概念须先统一术语、逐步编写，再按句子、段落和概念含义逐项审校；不通过先改写再复核。每段一个主题且不超过六句；复杂首次定义在正文展开，表格用于摘要与导航。审校不新增学习记录表或用户负担。
- 解释深度以帮助用户理解地图、进入原始材料为准，不展开为教材或教程的简化版本。

### 阶段判断与时间大纲

- 阶段指南说明学习目的、必要基础、材料方向及纲领性的能力标准，标准应能说明学习者应能够解释、判断或完成什么。
- 自我测验仅提供方式与方法，例如自行复述概念、重建论证、解释适用条件，或利用原资料中的练习和实践检验理解。用户自行执行并根据需要与 AI 深入交流。
- 不编制具体考题、答案、评分程序或考试流程，不要求提交学习成果，不建立学习记录表或掌握度跟踪。
- 用户没有提出时间诉求时，不强制添加时间规划。用户提出大致时间要求时，给出方向性的阶段大纲，不安排精确到每天的任务。
- 可提供两周、一个月、半年等适合当前主题的预设方案，不固定要求具备这些档位。每个方案说明适用基础、大致投入、预期能力与未覆盖范围。
- 时间估计与用户目标明显冲突时，说明依据并提供范围、深度或投入上的调整选项，由用户决定，不擅自修改目标。

### 产物与更新

- 多份 Markdown 构成主要 Wiki，具有清楚的阅读入口和可用的内部导航。正文应能解释地图关系，基本使用不依赖 HTML。
- 概念、阶段和资源通过链接复用，避免为不同页面重复维护相互矛盾的解释。
- Agent 根据当前内容判断是否生成 HTML。生成时以知识地图、领域总览和入门导览为主要用途，不将其扩展为演示、模拟、练习或进度管理系统。
- HTML 与 Markdown 应来自同一套内容依据，保持范围、概念关系、资料和学习方向一致。具体生成机制在实现时选择，不预设框架或外部服务。
- 持续维护由用户发起。收到目标变化、材料太难、资源失效等反馈后，重新核查受影响的内容，保留仍然有效的结构与资料；只有必要时才整体重组。
- 更新对象是指南及其资料判断，不是学习者活动日志。默认不建立后台监控、定期更新或通知机制。

## 测试决策

### 已确认的主要验证边界

以一次完整 Skill 调用为主要边界：输入用户请求、已知背景和可访问资料，观察实际澄清对话及生成或更新的 Wiki。此边界覆盖从需求判断到交付产物的外部行为，不为每个逻辑职责分别增加测试接口。

用户已于 2026-10-16 确认该验证边界。方案确认与实际行为验证分别记录，本文不将计划中的测试视为已经通过。

### 好的验证应检查什么

- 检查地图关系是否有意义、路线是否适合背景、推荐是否有可回查依据，以及概念解释是否帮助初学者理解。
- 同时检查应发生与不应发生的行为：必要时先问再搜集，信息齐备时不重复问；不生成考题、学习记录和每日任务；不为凑格式强制生成 HTML。
- 不以固定文件名、固定标题、特定措辞、文件数量或字符串命中代替语义验收。
- 对链接、文件可达性和可选图表使用与实际产物相称的静态或渲染检查。需要浏览器的产物应实际查看；只做语法检查时明确没有验证渲染。
- 使用可控资料检查可回查性和证据边界。若有真实联网试用，单独记录实际核查范围，不能用离线样例证明资料仍然在线或内容最新。

### 需要覆盖的行为场景

| 场景 | 主要验收点 |
| --- | --- |
| 基础或目标不明确 | 先补足必要信息并等待回答，未提前展开该领域资料搜集 |
| 目标与背景已经提供 | 使用已有信息，不重启固定问卷 |
| 科学技术主题与中国历史主题 | 根据领域选择资料语言、来源类型与知识关系，不套用同一套推荐清单 |
| 领域很大但个人目标有限 | 全景与目标主线可区分，有取舍理由，资料量不替代覆盖判断 |
| 主线资料可检查或关键内容无法取得 | 推荐深度与实际核查范围一致，无编造的章节、课次、页码或已读声明 |
| 初学者面对抽象关键概念 | 准确解释与费曼式通俗解释一致，术语稳定，类比局限明确 |
| 用户提出两周或半年等时间诉求 | 方案有对应基础与可达目标，只有方向性阶段安排，无每日任务 |
| 用户需要阶段自检 | 给出能力标准与方法，无自行编制的具体考题、评分或学习记录表 |
| HTML 有助于总览或没有明显必要 | 可合理选择生成或省略，Markdown 均完整；生成时内容一致且仅承担导览职责 |
| 更新已有 Wiki 的局部内容 | 只修改必要范围，保留无关的有效内容，不擅自改变用户目标或启动监控 |

### 仓库先例与实施时的使用方式

Book Study 已有以真实请求、受控原始材料和实际 Markdown 产物为对象的行为试用及验证记录，也将链接检查、内容判断与未验证项分开。这些可以作为本 Skill 验证方法的先例，但其正文精读、独立 AI 互动指导等职责不迁移为本 Skill 的要求。

Ten-step-learning 的结构校验与质量记录可作为区分“格式通过”和“行为通过”的先例，不自动继承其十步流程、考试、互动循环、发布门禁或宿主验证范围。

规格整理阶段仅检查了文档一致性、引用与仓库入口；后续源码制作阶段开展的行为试用及其实际范围应回查验证记录，不能将上述场景列表视为全部已通过。真实学习效果仍需实际读者证据。若添加脚本，应运行与实际行为相关的检查，不为可逆文档改动或实现的文字复述额外编写测试。

## 范围之外

- 系统教程、教材改写、教材或课程的简化版本，以及替代原始材料的大量正文讲授。
- 自行编制具体考题、答案、评分体系、考试流程或练习系统。
- 学习记录表、打卡、掌握度跟踪、进度面板和学习者活动日志。
- 精确到每日的课程表、任务分配或自动调整日程。
- 默认后台监控、定期搜集、资料更新通知或其他自动化维护。
- 必须生成 HTML、复杂演示、模拟器、练习应用或完整网站系统。
- 材料费用评分、预算优化、购买课程、采购教材或工具。
- 覆盖所有分支到相同深度、固定数量的资源、固定数量的概念页，或无依据的全面性声明。
- 修改已有 Skill、强制依赖其他 Skill、全局安装或发布插件。
