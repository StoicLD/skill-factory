## 行为试用

使用独立 Agent 实际执行 Skill；只提供请求、Skill 路径、最小材料与隔离输出边界，不提供预期答案。材料为本次编写的短篇虚构教学文本，不冒充出版物。对话测试由主 Agent 分轮提供读者回答，没有让执行者自行编造读者答案。

| 场景 | 实际观察 |
| --- | --- |
| 技术工程导读，初始只有材料与输出位置 | 依次询问类型、模式与基础、目标；每次等待回复。接受“不确定，你来判断”和“没有特别目标”；第三轮后直接生成 3 个文件，无第四轮审批。 |
| 理科材料精读，读者先归为技术工程，其他需求已知 | 直接采用已知信息；根据定义与证明选择理科分析，以工程应用作为辅助视角。4 个文件保留两侧差值推导、数值反例、应用边界，概念关系表与知识树承担不同作用。 |
| 历史材料部分已读，总结与拓展，无特别目标 | 不重复问卷。4 个文件区分发言记录、作者解释与推断，回答“谁更可信”时保留证据限制。独立 AI 指导携带书籍、读者、材料路径、摘要、单问题互动与适应规则，未写成“用户已经掌握”。 |
| 只有目录的混合类型全书精读请求 | 生成 2 份受限产物，明确标为精读准备；类型判断为暂定的理科与工程混合。关系表标记待正文核验，自拟例子不冒充书中内容，并指出继续所需的具体原文。 |
| 技术工程精读，与理科试用使用同一模式 | 3 个文件按任务运行、状态变化和崩溃窗口解释重投、事务与外部邮件边界；没有套用定理证明模板，也未声称实际运行系统。 |
| 历史精读，与前两类使用同一模式 | 3 个文件按时序、行动者、公开发言、作者解释、代表性与因果证据拆解第一章；关系表与分层知识树互补，未泄露第二章情节。 |

六个场景共生成 19 份 Markdown。主 Agent 检查实际产物中的概念解释、上下文衔接、关键依据、原文定位、图谱关系及互动指导：导读围绕“执行成功但确认缺失”补概念；理科精读保留代数中间步骤；工程精读比较故障状态；历史精读保持证据层次；总结给出可执行的后续任务。没有仅凭标题齐全判定合格。

逐一检查生成产物的本地文件链接与使用到的标题锚点、原文路径、围栏及范围。针对未读第二章，结合全文件阅读与具体情节标记扫描检查剧透。脚本检查用于发现路径和结构问题，内容判断仍以实际阅读为依据。

## 验证边界

- 这是短篇 Markdown 材料试用，尚未验证长篇出版物、扫描 PDF、EPUB 提取或大规模章节处理。
- 实际试用使用文字关系图或关系表与 Markdown 知识树，没有执行 Mermaid 或 Obsidian 的真实渲染。
- 全程离线，没有测试外部资料搜索、链接时效或资料服务访问。
- 已检查 AI 互动指导的独立信息完整性；尚未与真实读者在新会话开展连续自适应互动，也未测量学习效果。
- 未验证全局安装后的自动发现或宿主界面行为；基础校验通过不等于行为在所有模型和宿主上恒定。

原始试用材料和产物位于 workspace 的临时区域，检查完成后删除；此处只保留可复核的场景、观察与验证范围，不将样例加入 Skill 的运行依赖。
