# Book Study

帮助读者理解、研究和消化一本书。导读、精读、总结与拓展是本 Skill 的三种模式，共享需求问答、材料核验和文件交付流程。

## 1. 按三轮理解需求

先从当前请求和前文提取已知信息，按下面三轮逐轮补齐。每次只处理当前轮；发出本轮问题后等待回答，再进入下一轮。用户已经明确给出的答案直接采用，整轮信息齐备时可直接进入下一轮，不为凑足次数重问。三轮需求尚未确定时，只做材料检查和需求梳理，不生成整套成品。

“不确定”“你来判断”“没有特别目标”都是有效回答，记录用户原话并采用相应判断或默认值；沉默不等于回答。把 Agent 判断与用户表述分开。用户中途修正信息时更新受影响部分，保留仍有效的回答，不重启问卷。

### 第一轮：书籍类型与分析方法

询问书籍大致属于：**人文社科、技术工程、理科理论、混合类型或不确定**。书籍尚未确定时，在同一轮简洁请用户提供书名、作者及手头材料；版本仅在辨认原文、页码或技术差异有用时确认。材料可为全文、部分章节、目录、已有笔记或仅书名，不另加材料问卷。

收到回答后，结合实际取得的目录、前言、正文等独立判断，用一两句话说明本次采用什么分析方式、为什么。用户分类是线索；材料不足时说明判断暂定。可以有主类型与辅助类型，不同章节也可以采用不同方法。

| 类型或内容 | 分析时重点看什么 |
| --- | --- |
| 人文社科 | 核心问题、历史与社会语境、概念、作者立场、论证和证据、不同解释与边界。历史侧重时序、行动者、条件与因果；文学侧重叙事、人物、主题和表达，不强套社会科学论证模板。 |
| 技术工程 | 要解决的问题、系统组成与运行机制、模块关系、设计取舍、约束、失败情况和实践方法。区分原理、具体实现、版本相关细节，避免工具名词清单。 |
| 理科理论 | 研究对象、定义、前提与假设、定理或模型、推导、直觉、例子、反例和适用范围。明确区分严格证明、经验规律与类比，类比不能替代证明。 |

这是选取分析方法的依据，不是每本书都必须填满的模板。方法应体现在后续实际解释中，不能只改分类标签。

### 第二轮：产物模式及相关信息

模式未确定时，简洁介绍并让用户选择一个主模式：

- **导读**：准备阅读，或阅读时发现背景和基础不足；请一并说说相关基础和主要困难。
- **精读**：系统拆解原书内容、概念与结构；请一并说明分析全书还是指定章节，以及有哪些原文可用。
- **总结与拓展**：读完全部或部分后巩固理解、继续研究；请一并说明已读范围、当前理解及仍有疑问的地方。

只请用户回答所选模式对应的信息，不要求填写其他分支。模式已知时，直接补充该模式必要信息；未表达的个人理解或观点记为“待了解”，不强迫自评。背景未说明时采用易进入的讲解起点，并标记“基础待了解”，不能断言用户是零基础。

默认一个主模式。仅在用户明确要求组合时加载对应的多个模式参考，围绕同一入口和材料表合并产物，共用概念解释与图谱，通过链接复用而非重复生成。

输出位置尚未说明且无法从 workspace、AGENTS.md 或目录习惯判断时，可在本轮附带询问。用户不指定时由 Agent 选择合理位置。关键范围仍不确定时采用实际可用材料的明确范围并说明；不把未知的“已读范围”自动当成全书已读。

### 第三轮：本次希望达成的结果

询问：**“使用这次生成的材料后，你最希望自己能够理解什么、解释什么，或完成什么？”**

可结合前两轮给出少量具体例子供参考，但不替用户预设目标。如果目标已在前文明示则直接采用；用户没有特别想法时采用所选模式的默认目标，不再追问。目标影响重点、深度、案例与阅读路线，不取代该模式的基本职责。

完成后简短归纳：分析对象和范围、书籍类型与分析方法、产物模式、读者基础与本次目标、输出位置。直接开始生成，不增加第四轮审批。

三轮完成后若发现关键原文缺失，按下节说明缺口并交付有依据的部分；如仍需用户补材料，提出具体材料请求即可，不重新做需求问卷，也不把受限结果称为已完成的正文精读。

## 2. 确认材料与证据边界

生成前实际检查可访问的材料，记录材料名称或路径、作者及版本（未知则标明）、可读取范围、章节或其他定位方式。文件存在不代表已读取；扫描件无法识别或提取不全时明确实际可读范围。

- **全文或部分原文**：以实际读取的原文为主；明确本次覆盖哪些章节，哪些尚未分析。
- **仅目录**：可做结构预览或暂定阅读路线，不能声称正文精读或重建作者完整论证。
- **仅笔记**：可以整理用户笔记，标明其来源；未对照原文的记录不能直接升级为作者观点。
- **仅书名**：可结合核验过的书目信息做有限导读；缺少原文的内容不能凭常识写成书中事实。

重要分析使用已核验的章名、节名或位置回指原文。页码仅在实际核验且版本明确时使用；PDF 文件页序与书内印刷页码要区分。无稳定页码时用章节、节名及可定位的短语，不编造编号、引文或来源。

在需要辨别归属的段落标明**作者观点、外部补充、模型推断、用户观点**，不要把自己的例子说成原书案例。保留推断依据与不确定性，引用只取解释所需的短片段，以自行讲解为主体。

外部资料仅为解决当前缺口而查证，记录实际使用且核验过的链接；版本或时效相关内容记录核验日期。无法联网或无法核验时说明限制，不声称已经验证。遵守用户的离线要求；不默认把书籍或私人笔记上传到外部服务。

用户限定的章节和不剧透要求约束**所有文件**，包括入口、图谱、资料说明与 AI 互动指导。区分“可用材料”“已读范围”“本次分析范围”，未读内容只在允许的边界内提供阅读指引。

## 3. 按模式组织与讲解

只加载当前选择的参考：

- **导读**：读取 [references/guide.md](references/guide.md)。默认目标是让缺乏相关知识和经验的读者能够进入原书，理解讨论对象、必要概念与读法。
- **精读**：读取 [references/close-reading.md](references/close-reading.md)。默认目标是把原书拆成可理解、可回查的结构，并看见整体关系。
- **总结与拓展**：读取 [references/synthesis.md](references/synthesis.md)。默认目标是整合理解、识别未解决问题、找到后续探索方向，同时生成独立的 AI 互动指导。

写作围绕读者理解所需的中间环节展开：概念先用白话和具体例子解释，再给专业表述；重要结论交代问题背景、依据与必要推导；段落之间说明上一部分解决了什么、下一部分为何出现。篇幅服从理解需要，避免用重复扩充字数。

图谱中的节点应能传达概念含义，边说明依赖、包含、对比、因果、前提、推导或反馈等实际关系。分清作者论证中的因果与仅有相关性。图太密时拆成主干与局部图，正文仍应能独立解释关系。

补充资料说明：补什么、为何适合此读者、读哪部分、读后应能理解什么。核心讲解在当前产物中完成，不能用链接清单替代。

## 4. 交付一组 Markdown 文件

先检查目的地的 AGENTS.md、命名习惯和已有文件。用户指定目录就使用该目录；否则在允许的 workspace 笔记或输出区域选一个清晰的书籍子目录，不把读者产物写进 Skill 源码目录。出现同名笔记时新增独立子目录或不冲突的文件名，不覆盖已有笔记或进行无关整理。

提供一个入口文件（如 `00-阅读入口.md`），说明本次范围、读者目标、材料与限制、建议使用顺序，并链接主题文件。文件数量由内容决定：避免巨型文件，也避免每个概念各拆一页。用户实际表述与采用的默认值在入口中分开记录。

使用 Obsidian 可读的标准 Markdown 标题、列表、内部链接。优先相对 Markdown 文件链接以便文件夹整体迁移，复用当地已有约定；必要时用 Mermaid 呈现关系，并提供可读的文字解释。不要求第三方插件，不默认生成 HTML、PDF、XMind 等格式。

## 5. 交付前检查

检查完成判据，而不仅是目录与标题是否齐全：

1. **需求与范围**：三轮已完成或由明确的已有答案覆盖；采用有效的不确定回答；实际范围、版本与剧透边界一致。
2. **讲解质量**：抽查核心概念是否有可理解的解释和例子，重要结论是否有依据和中间环节，段落能否顺着读；按所选分析方法审阅关键单元。
3. **模式职责**：导读补足进入原书的门槛；精读保留内容拆解、概念关系与分层知识树；总结与拓展推进已读理解，且 AI 互动指导脱离当前会话仍能使用。
4. **文件可用性**：逐一核对入口与内部链接、材料及笔记路径、标题层级、代码围栏；检查 Mermaid 节点和边与正文一致。可用渲染工具时检查图表渲染，未渲染则明确未验证，不把语法目检称为渲染通过。
5. **交付状态**：明确已完成、有依据但受限、等待材料的部分，以及未验证项。给出入口和必要的主题文件路径，说明建议从哪里开始。

验证所需样例放在临时位置，不覆盖历史笔记；用完清理本次可丢弃的临时产物。
