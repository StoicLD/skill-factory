# 精读

仅在选择精读模式时加载。目标是将实际可用原文拆成可以理解和回查的结构，同时形成整体认识。“高层次”指看见内容间的关系，不是压缩成抽象口号。

## 原文覆盖与拆解

先确定实际读到的范围，再选择有意义的单元：章节、主题、论证阶段或系统模块。入口说明这些单元怎样共同推进中心问题。只有部分原文时仅精读该部分；目录不能支撑正文级拆解。

每个单元围绕正在解决的问题组织，按需要解释关键概念、主张、推导、案例、证据和限制。明确承接前文的哪些结果、为下文提供什么。保留重要中间环节，不用一句结论替代作者的论证或计算。

按内容选择拆解方式：

- **人文社科**：从问题和语境进入，解释概念、论据怎样支持结论，区分事实材料与作者解释，说明竞争解释是否真的有依据。历史章节区分先后顺序与因果机制；文学章节围绕叙事、人物行动、意象与表达细节展开，并回到文本证据。
- **技术工程**：以具体输入或任务沿系统运行一次，解释模块职责、状态或数据如何变化、设计为什么这样取舍。结合约束分析失败情形，区分原理与书中版本的实现；没有实际运行过的代码不能称为已验证。
- **理科理论**：解释对象与符号，列出必要前提，连接定义、命题和推导。对关键证明保留读者理解所需的步骤；原文省略或自身无法确认的步骤标明缺口。用例子建立直觉、反例界定条件，始终区分证明与类比。

这些是分析视角，不要求每单元套同一张表。混合章节可组合视角，例如先推导概率模型，再分析模型进入软件系统后的近似与代价。

## 概念地图：解释怎样关联

选对理解主线有作用的概念，用文字关系表或 Mermaid 图表达依赖、包含、对比、因果、前提、推导和反馈。节点给出可辨识的含义；边标注关系含义，必要时说明成立条件。复杂图拆出局部图并链接到解释。

例如真实材料支持时，可表达“独立性假设 —允许分解→ 联合概率”，并解释这里的独立性是什么、缺少它为何不能这样分解。不能只有“独立性 → 概率”两个关键词，也不能把这个示例当成待分析书籍的内容。

## 分层思维导图：解释怎样组织

另提供 Obsidian 可直接阅读、折叠的知识树，用标准 Markdown 标题层级或嵌套列表。每个主要节点至少说明它处理的问题、概念含义或在主线中的作用；关键节点链接到详细拆解及原文定位。无需安装插件。

概念地图负责跨单元关系，知识树负责分层组织与回查；二者可以放在同一文件的不同部分，不能机械复制两份相同目录。Mermaid 是补充，不能替代必需的 Markdown 知识树。

## 原文定位与回查

在重要概念、论证、设计取舍或推导附近提供已核验定位。可以共用一个单元的来源说明，但读者应能知道分析对应原文哪一节。把原书例子与为解释而新增的例子区分开；外部补充链接不能冒充原文证据。

## 完成判据

抽查一条核心主张：能沿“问题—前提或证据—中间过程—结论—边界”读通，并找到原文依据。再抽查一条跨单元关系和知识树中的一个分支，确认前者解释关联，后者支持定位。对文学等不以命题论证为主的内容，改查文本细节怎样支持对叙事或主题的解释。
